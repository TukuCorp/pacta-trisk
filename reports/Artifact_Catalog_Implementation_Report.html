Artifact Catalog Implementation Report 2026-09-13

Plan: plans/2026-09-13-artifact-catalog-plan.md — all 5 phases implemented in full. Design record: research/2026-09-13_artifact-catalog-design-grill.md; decision: docs/adr/0001-artifact-catalog-owns-locations.md; glossary: CONTEXT.md.

Objective

Nine places spelled Artifact paths by hand and two of them were already wrong: the step registry declared synthesis_output/trisk/<sector> where TRISK writes <sector>_demo, and a single trisk_input_root where the real inputs sit under <root>/<sector>_demo/. Because validate_step_dependencies() compares strings, step ordering was being validated against paths nothing writes.

This work gives every Artifact one owner — R/artifact_catalog.R — that knows each Artifact's key, producing Step, repo-relative output path and Snapshot path; makes every R consumer derive its list from it; exports the resolved catalog into the Snapshot as artifact_catalog.json; and has the Streamlit app resolve every table path from that export. It is a refactor under the repo's existing acceptance gate: no CSV and no gated report changed.

Phases

PHASE-01 — Catalog module

New R/artifact_catalog.R: artifact_catalog(cfg) (one row per resolved Artifact — 83 rows for MCB: 29 engagement-scoped + 3 sectors × 18), artifact_path(cfg, key, sector, where) and write_artifact_catalog_json(cfg, path). Rows carry only the five flags that have a consumer today (history_headline, timestamp_class, gated_html, disclaimer_required, data_source_check). 13 tests, including a transition test pinning the union of every hand-typed path literal.

R/artifact_catalog.R, tests/testthat/test_artifact_catalog.R, NAMESPACE (3 exports), man/ (+3 .Rd)

PHASE-02 — Registry, planner and PACTA driver read the catalog

The six hand-written produces_fn/requires_fn closures are deleted; entries declare requires by artifact key and .attach_dependency_fns() derives both closures from the catalog. The manifest path, row_count_files validation (refuses an uncatalogued Snapshot path) and the PACTA facts sidecar also come from the catalog. Dependency edges are unchanged; the paths they name are now real.

R/step_registry.R, R/engagement_plan.R, scripts/run_engagement.R, scripts/pacta_vietnam_scenario.R, 3 test files

PHASE-03 — Snapshot copier, run history and refresh audit

scripts/refresh_dashboard_data.R copies exactly the rows the catalog says have a Snapshot location (files → PNG groups → reports → TRISK files/figures/grid → manifest.csv → analytics) and writes <snapshot_dir>/artifact_catalog.json. Run history takes its headline set from the history_headline flag; the refresh audit resolves its reads and writes by key. The snapshot-contract test became a catalog-versus-Snapshot check: every catalogued Snapshot path exists, and no uncatalogued CSV/parquet/json hides under pacta/, trisk/ or analytics/.

scripts/refresh_dashboard_data.R, scripts/record_run_history.R, scripts/generate_refresh_audit.R, tests/testthat/test_snapshot_contract.R, dashboard/data/artifact_catalog.json (67 artifacts, committed)

PHASE-04 — The gate derives its lists

TIMESTAMP_BASENAMES, GATED_HTML_PATHS, DISCLAIMER_HTML_PATHS and INV-003's candidate list are computed from the mcb-demo catalog; the values are set-equal to the literals they replace (including order for the first two). A new gated report is now added by setting a flag on its catalog row. The tool sources the config + catalog with the same two-candidate pattern it uses from tests/testthat, and merges the config without the loader's file-existence validation so it can be sourced from either working directory.

tools/verify_refactor.R

PHASE-05 — The dashboard reads the export; docs; cleanup

dashboard/lib/loaders.py gained artifact_catalog_path(), load_artifact_catalog() and artifact_snapshot_path(key, sector); every table loader resolves from the export (page-facing keys unchanged, with the two documented aliases combined → top_borrowers and company_trajectories_latest → company_trajectories). Four dead hand-typed path helpers were deleted. README and NEWS describe the catalog; the PHASE-01 transition test is removed.

dashboard/lib/loaders.py, dashboard/tests/test_loaders.py, dashboard/tests/test_analytics_page.py, dashboard/data/README.md, NEWS.md

Deviations from the plan (all deliberate)

  • test_engagement_plan.R's synthetic .test_cfg() now carries the full paths key set: the catalog refuses a config missing a location key, and a synthetic config that cannot resolve is not a useful test double. Behaviour assertions are unchanged.
  • The copier's intra-sector file order follows catalog order (input-side rows first); content and the manifest.csv bytes are unchanged.
  • load_trisk_tables() resolves manifest.csv through the catalog too, and the now-unused trisk_manifest()/trisk_path()/trisk_sector_path()/reports_path() helpers were deleted (pacta_path() and analytics_path() are still imported by tests).
  • Filtered-run plan_engagement_run() calls in test_engagement_plan.R now warn about the previous-run sector_priority_ranking.csv read; that is the pre-existing dependency warning surfacing with a real path instead of the old degenerate one, and no test asserted silence there.
Known ordering defect this plan intentionally leaves in place: sector_prioritization and the analytics copy consume the previous run's Snapshot. Reordering changes the pinned step order and the manifest, so it belongs in its own plan — the catalog's snapshot_path column turns that follow-up into a one-line requires change.
